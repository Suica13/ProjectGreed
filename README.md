单位、武器套件、编组与部署的最新配置见 [单位与编组配置](单位与编组配置.md)。可用单位、各类防护、原 MOD 素材与音乐播放列表均由项目内 JSON 配置。

基于 Gundam Wars MOD 素材制作的浏览器回合制战术游戏原型。当前目录141种单位，包含0079两阵营科技树第一页的135个作战条目及此前保留的机体。新增坦克、飞机、直升机、两栖与海军单位、侦察及整备舰船；复杂原MOD技能的接入状态详见[0079第一页移植核对](0079第一页移植核对.md)。MS拥有武器套件与固定武装，萨拉米斯使用独立炮塔模块。支持保存编组、出生区部署、1v1／2v2／3v3／5v5 IP联机、离线房间与AI对战。右下角 BGM 播放器支持暂停、播放与随机下一首，六首曲目可离线循环播放。

对战统一使用房间流程，热座模式已取消。主菜单按“玩家阵营／玩家ID／切换阵营”和“开发／编成／战斗／回放”排列。点击“战斗”可选择单机创建房间，或连接服务器后创建／加入联机房间；创建房间时可选择常规战或快速战，房主也可在房间规则中切换。常规战按角色阵营及科技解锁限制编组，快速战允许任意阵营单位；两种模式都遵守房间禁用标签。只要房间仍有其他玩家或观战者在线，掉线后显示居中的“连接已断开”弹窗，点击“重连”恢复当前席位；刷新页面仍会自动恢复；所有人离线时房间立即解散。

网页首先进入 Menu，主菜单和房间准备期间不绘制战斗场景。入房后可选择队伍1、队伍2或观战席，全部出生席位填满并准备后进入最终编组，全员确认后部署；游戏中通过“房间席位”随时切换角色。点击“主菜单”需确认离开，退出只释放自己的席位，其余玩家仍留在房间。

开发界面引用原 MOD 0079 第一页科技树，展示联邦8项、吉翁9项科技的前置关系、单位解锁及所需阵营科技点。当前没有科技点获取或开发操作，初始科技点为0；联邦和吉翁只预解锁各自的基础科技。联邦默认编组为米迪亚、飞鳐×2、Type61×4，均来自联邦基础科技。科技目录见 `shared/development-tree.json`，需要重导时使用 `tools/import-0079-tech.py`。

阵营标签、全部单位耐久与新 COST 档位、导弹定位详见 [遭遇战与阵营平衡](遭遇战与阵营平衡.md)。

## 战斗界面

手机打开页面时先提示“推荐以横屏游玩”，点击继续后进入主菜单；只提示一次，不锁定手机方向。

地图使用全宽布局。选中单位后，屏幕右下侧横向显示移动、攻击、技能与待机指令（结束行动按钮上方），右侧浮窗按“概览／武装／技能”分页显示。关闭资料浮窗不会取消选择，点击底部单位名称可重新打开。移动和攻击都必须先点指令按钮，再选择位置或目标；选点期间隐藏资料窗，下方提供取消按钮。选中攻击目标后，底部展开可用武器与当前攻击计划，确认后才提交。Esc优先取消当前选点／编辑，再次按下可取消单位选择。聊天与LOG嵌入屏幕底部，可收起或扩大；单位名单和地形图例通过底部按钮打开。部署确认与结束行动共用底部右侧位置。

战斗布局样式集中在 `client/battle-hud.css`，显示状态与浮动指令定位在 `client/battle-hud.js`；它们复用原有游戏指令，不另写战斗规则。修改后运行 `npm run build` 同步发布版与开发者版。

## 生产与个人库存

主菜单“生产”提供单位生产和当前武器套件购买。资金和物资与驾驶员、编组、科技一起保存和导出；单位按原工厂最便宜的武器组生产，套件独立入库、在当前编组中占用，不足时退回素体。价格、批次数量与时间备份规则见 [生产与库存](生产与库存.md)。单位库存不足时提供整单补齐生产；服务器在编组确认及开局时排除缺货单位。正常战在对局正常结束时扣除损毁单位；快速战、续读存档及中途离开免扣库存。击毁及胜利收益、新存档赠送见同一规则文档。

## 从仓库启动

安装 Node.js 22 或更高版本，克隆仓库后在工程目录运行：

```sh
npm ci --omit=dev --ignore-scripts
npm start
```

发布版：<http://127.0.0.1:1313/>

开发者版：<http://127.0.0.1:1313/developer.html>

端口由根目录 `cfg.json` 配置。构建只生成 `public/client.html` 和 `public/developer.html`，服务器首页直接提供客户端。开发者版单位预览与科技开发界面提供“修改属性 / 保存属性”；单位覆盖对应的 `assets/units/<ID>/unit.json`，科技树覆盖 `shared/development-tree.json`。保存后在设置中点击“重载”，重新校验、构建并加载新属性。请先退出所有房间；文件保存和重载需通过本机服务器访问，直接打开 HTML 不能写项目文件。

仓库保留已构建的 `public/*.html`，可直接用浏览器打开。联机时仍需运行服务端。仓库不提交 `node_modules`，首次运行需执行上面的依赖安装命令。

按需运行打包命令后，给玩家分发可使用 `dist/ProjectGreed-V15-client.zip`，解压后双击 `client.html` 即可离线游玩。修改源码后运行 `npm run package:client` 重建 HTML 和客户端 ZIP；打包脚本需要开发电脑安装 Python 3，玩家无需安装。

`project.json` 统一保存项目名称与显示版本，构建时注入网页，服务端启动与 `/health` 也显示同一标识。反击命中率为正常最终命中率的 75%，每台单位每回合只能选中一名敌人反击一次。V11 的命中、伤害、应战、耐久和 COST 调整见 [数值与 COST 估算](单位COST估算.md)。每次队伍交接递增回合编号，播放「结束回合 → 回合编号 → 开始行动」横向 Cutin。没有合法移动或攻击时等待 1 秒自动结束回合；联机由服务端计时。地图支持双指、滚轮及按钮缩放，上限随地图及画布尺寸自适应（至少500%，保证单格可放大到约160像素），单位始终显示耐久条和黄色 EN 条，300% 及以上额外显示单位名称；放大后按住拖动平移，点击「复位」显示全图。

## 开发检查

```sh
npm run build
npm test
```

主菜单可设置玩家ID（显示昵称）。房间与战局均支持聊天；左侧单位列表与下方日志分别滚动。对局结束后30秒自动返回原房间，房主也可立即带全员返回，重新准备即可再开一局。房主离线时权限自动交给其他在线成员。

详细玩法、局域网连接、断线恢复和UI编辑说明见 [使用说明](使用说明.md)。原始美术素材来自 Gundam Wars MOD。

开发者版支持独立场景预览、界面元素选择与拖拽、战斗机体位置和倍率调整，以及桌面／平板／手机布局。无需实际打一场战斗即可预览命中、未命中、反击和击破。

源码职责、属性编辑步骤、JS 常用写法和检查命令见 [代码导读](代码导读.md)。

语言切换、单位三语名称配置与手动添加单位步骤见 [语言与单位扩展](语言与单位扩展.md)。主菜单会识别浏览器语言，未匹配时使用英文；根目录 reload_units.bat 用于扫描单位目录、校验素材并重建网页。

房主可在房间中选择地图和每位玩家的编组 COST 上限（默认900），仅更换地图后所有玩家重新准备。玩家可自行选择队伍与空闲出生点，每人独立部署并操作自己的编组；同阵营共享回合，各自结束行动后交接。房间中房主金字、自己蓝字、其他玩家白字，聊天窗与操作区分别滚动。地图与多人规则见 [地图与多人房间配置](地图与多人房间配置.md)。

地图圆环按玩家视角显示：自己绿色、同队友军蓝色、敌军红色，均为俯视正圆。点击单位可查看所有者与队伍，非行动方也可查看。新增五台单位的原MOD接入、武器与数值说明见 [新增单位说明](新增单位说明.md)。

房主刷新或短暂断线时，在仍有其他真人在线的房间中保留10秒重连时间；主动离开立即移交，超时后按在线真人的加入顺序移交，跳过AI。换队或观战不改变房主身份。

房间玩家席位按“玩家ID／空位｜出生地｜准备状态”显示，观战名单每行三人。“加入队伍”由服务器选择该队当前空闲出生点，队伍满员或已经加入时有明确提示；也可点击空出生点直接选择。

房间和游戏共用聊天记录与发送频道选择。所有有权限查看的消息按顺序显示在同一个聊天面板中，以 `[全部]`、`[队伍1]`、`[队伍2]`、`[观战]` 前缀区分；切换发送频道不会隐藏其他频道消息。观战者的发送菜单只提供全部和观战，但聊天记录同时包含两队消息：

| 身份 | 全部频道 | 本队频道 | 另一队频道 | 观战频道 |
| --- | --- | --- | --- | --- |
| 队伍玩家 | 收发 | 收发 | 不可见 | 不可见 |
| 观战玩家 | 收发 | 只读队伍1 | 只读队伍2 | 收发 |

频道权限统一放在 `shared/chat-channels.js`；`shared/room-engine.js` 在实时发送、快照、重连和重复请求时校验权限。切换队伍或观战身份后，界面重新筛选可见历史；已经看过的消息无法撤回。每个房间最多保留最近100条消息。

房主通过 AI 行的设置按钮选择简单／中等／困难（75%／100%／125%性能）及50%～150%编组预算。AI独立阵营倾向已移除，改为遵守房间和所在队伍的禁用阵营、年代标签。最终编组可查看队友头像与总COST并修改自己的编组；先禁用标签不符或单机超限的单位，再从编组末尾向前禁用至总COST合规。超限显示OVER COST，禁用标签显示“不被允许的单位”，文字均位于黑色半透明遮罩上方；这些单位不会进入战场。详见 [遭遇战与阵营平衡](遭遇战与阵营平衡.md)。

聊天频道选择位于输入框左侧，消息格式为 `[队伍1]玩家ID:聊天内容`（全部／观战频道对应显示其频道名）。战斗演示由中央线分区，格斗单位接近对方区域完成攻击后返回，挥刀使用原MOD粉色／黄色序列帧，战斗Ring与地图Ring均为俯视正圆。


编组数量上限默认为12台，房主可在房间内设置3～12台；仅更换地图会取消准备，联机和离线房间使用相同规则。AI优先填满允许的单位槽位，在COST或阵营最低造价不足时减少台数；参考当前地图的地面／宇宙标签，优先选择适应性更高的单位，并随机选择合法武器套件。预算或限制不足时允许使用适应性较低的单位，但不会选择当前环境适应性为0的单位。编组列表显示阵营、名称、图标、当前武器套件、COST和单位介绍；点击单位可查看详细属性并修改武器套件。导弹不再显示额外说明文。

### 环境表现与迷雾特效

- 水中适应性大于零的普通单位可以下水；气垫单位继续使用陆地适应性，飞行单位使用空中适应性，宇宙地图使用宇宙适应性。适应性按百分比影响命中、机动（回避）和移动；正适应性保留至少 1 格基础移动量。跨环境路径按进入格的适应性累计移动消耗。飞行单位不享受森林、废墟掩护。
- 下水有一次水花、下沉偏移和半透明表现；水花目前为程序绘制，`EnvironmentVisuals.drawWater` 保留寻找 MOD 原特效的 TODO。气垫不下沉，飞行单位上浮，战斗武器挂点与机体使用同一高度。
- 设置中的「单位阴影（实验功能）」默认关闭，只影响本机，宇宙中不绘制。迷雾边缘使用缓存遮罩柔化，不改变侦察与选取规则。
- 特效默认可以出现在迷雾内。特效定义、单位特效图层或武器 `projectile` 上设置 `visibleInFog: false` 可恢复可见区域裁剪。自定义图层可标注 `effect: true`。隐藏机体的效果通过 `effectActors` / `effectEvent` / `effectCombats` 专用演出数据同步，不加入可选单位、队伍 LOG 或侦察视野；这份数据仅包含演出需要的位置、型号与视觉状态，真实 HP、EN、命中概率和行动计划不随之发送。
- 回放播放器已接入沉浸模式：开启后隐藏 DOM 界面、地图标记、血条、名字与伤害文字，并跳过回合交接 cut-in；按 Esc 恢复。普通联机交战演出不会自动进入该模式。


### 对局记录：保存、回放与续局

主界面和战斗界面的「对局记录」是统一入口，提供保存、载入、回放本局和文字 LOG 下载。新对局自动记录已裁定状态的增量及每回合行动开始的完整检查点，不从文字 LOG 推测战斗结果，也不重新掷随机数。升级前的文字 LOG 不能转换成录像。

- 对局进行中仅可导出本队视角录像，不含全局视野或续局随机状态。对局结束／房主发起全员返回大厅后开放完整 `.greed` 文件；若要中途保存可续玩的对局，房主先一起返回大厅，再保存记录。续局恢复选定回合的开始状态，不恢复回合内中途操作。
- 未连接房间时，载入文件可直接本地回放；在大厅载入时，由房主上传，所有在线玩家一起回放。时间轴支持跳转，播放速度为 0.5×／1×／2×／4×。房主控制暂停、进度和速度，各人自行选择记录包含的队伍／上帝视角及对应 LOG。每段演出等待所有在线观众完成后推进，重连恢复当前段；后台观众仍可能让大家等待。
- 「从此回合继续」只在回合开始检查点启用。房主将原席位分配给在线玩家（含观战玩家）或 AI，保留单位、载员、部位、资源及随机状态，创建新 matchId 与分支记录。原录像不被改写。单机文件也可自动建立离线房间后续局。
- 沉浸模式隐藏战斗 UI、按钮、地图标记及文字，跳过回合 cut-in；Esc 恢复界面。它仅控制本人的显示，不改变共同回放进度。
- 文件携带格式版本和单位／武器／地图规则指纹；不兼容或损坏的文件拒绝载入。文件不含连接 token 或聊天记录。记录上限为 32MB／12000 个状态节点，达到上限保留已录内容并明确提示；不会静默丢掉开头。服务器仍以内存保存，关闭前应下载文件；不增加账号或数据库。
- 协议：`record_export`，`record_upload_begin/chunk/finish`，`replay_open/close/control/view/ready/fork`。大文件使用分块上传；普通消息继续限制为 16KB，单个记录分块最多 20000 字符。`replay_ready` 使用回放 ID 和片段 token，旧帧确认不能推动新帧；恢复与上传只允许房主在大厅操作。

编成修改自动保存到当前阵营的本地编组，包括命名、增删、换装与驾驶员分配；切换预设后立即记住当前选择。底部只保留“返回”，阵营下拉框位于同一行右侧；返回房间时提交编组给服务端校验。单位和驾驶员列表移除重复标题以增加可用高度。

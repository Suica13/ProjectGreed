# ProjectGreed V05

客户端的两个预设服务器配置在 `client/config.json` 的 `presetServers`：主要服务器与测试服务器各有独立连接按钮，界面不显示预设IP。打开连接界面会检测状态，可手动刷新，停留时每20秒复查；检测只读取房间列表，不占席位。自定义IP连接入口独立，`defaultServerAddress` 可留空或配置自定义默认地址；预设地址及其历史记录不会回填到输入框。修改配置后运行 `npm run build` 更新网页。服务端监听端口仍在根目录 `cfg.json` 配置。

单位、武器套件、编组与部署的最新配置见 [单位与编组配置](单位与编组配置.md)。可用单位、各类防护、原 MOD 素材与音乐播放列表均由项目内 JSON 配置。

基于 Gundam Wars MOD 素材制作的浏览器回合制战术游戏原型。当前可用单位为吉姆、吉姆加农、轻装吉姆、扎古II F型、大魔、陆战型吉姆、扎古II J型、扎古加农、格鲁古古、陆战型高达，各有主武器套件和固定武装。支持保存编组、出生区部署、1v1／2v2／3v3 IP联机、离线房间与AI对战。右下角 BGM 播放器支持暂停、播放与随机下一首，六首曲目可离线循环播放。

遭遇战统一使用房间流程，热座模式已取消。无需服务器时直接打开 `public/client.html`，选择“遭遇战 → 创建离线房间”，可选地图、设置 COST、添加或移除 AI，再准备与部署。联机时选择“遭遇战 → 连接服务器”，先在弹窗输入 IP 并连接服务器，成功后从分列房间列表加入或创建房间；可点击“刷新服务器列表”重新读取。只要房间仍有其他玩家或观战者在线，掉线后显示居中的“连接已断开”弹窗，点击“重连”恢复当前席位；刷新页面仍会自动恢复；所有人离线时房间立即解散。

网页首先进入 Menu，主菜单和房间准备期间不绘制战斗场景。入房后可选择队伍1、队伍2或观战席，全部出生席位填满并准备后进入最终编组，全员确认后部署；游戏中通过“房间席位”随时切换角色。点击“主菜单”需确认离开，退出只释放自己的席位，其余玩家仍留在房间。

阵营标签、全部单位耐久与新 COST 档位、导弹定位详见 [遭遇战与阵营平衡](遭遇战与阵营平衡.md)。

## 从仓库启动

安装 Node.js 22 或更高版本，克隆仓库后在工程目录运行：

```sh
npm ci --omit=dev --ignore-scripts
npm start
```

发布版：<http://127.0.0.1:1313/>

开发者版：<http://127.0.0.1:1313/developer.html>

端口由根目录 `cfg.json` 配置。开发者版左下角可开启UI布局编辑；导出的布局保存到 `client/ui-layout.json`，再运行 `npm run build` 同步更新开发者版和发布版。

仓库保留已构建的 `public/*.html`，可直接用浏览器打开。联机时仍需运行服务端。仓库不提交 `node_modules`，首次运行需执行上面的依赖安装命令。

按需运行打包命令后，给玩家分发可使用 `dist/ProjectGreed-V05-client.zip`，解压后双击 `client.html` 即可离线游玩。修改源码后运行 `npm run package:client` 重建 HTML 和客户端 ZIP；打包脚本需要开发电脑安装 Python 3，玩家无需安装。

`project.json` 统一保存项目名称与显示版本，构建时注入网页，服务端启动与 `/health` 也显示同一标识。反击命中率为正常最终命中率的 75%，每台单位每回合只能选中一名敌人反击一次。V05 的命中、伤害、应战、耐久和 COST 调整见 [数值与 COST 估算](单位COST估算.md)。每次队伍交接递增回合编号，播放「结束回合 → 回合编号 → 开始行动」横向 Cutin。没有合法移动或攻击时等待 1 秒自动结束回合；联机由服务端计时。地图支持滚轮及按钮缩放，上限随地图及画布尺寸自适应（至少500%，保证单格可放大到约160像素），单位始终显示耐久条和黄色 EN 条，300% 及以上额外显示单位名称；放大后按住拖动平移，点击「复位」显示全图。

## 开发检查

```sh
npm run build
npm test
```

主菜单可设置玩家ID（显示昵称）。房间与战局均支持聊天；左侧单位列表与下方日志分别滚动。对局结束后30秒自动返回原房间，房主也可立即带全员返回，重新准备即可再开一局。房主离线时权限自动交给其他在线成员。

详细玩法、局域网连接、断线恢复和UI编辑说明见 [使用说明](使用说明.md)。原始美术素材来自 Gundam Wars MOD。

开发者版支持独立场景预览、界面元素选择与拖拽、战斗机体位置和倍率调整，以及桌面／平板／手机布局。无需实际打一场战斗即可预览命中、未命中、反击和击破。

源码职责、可视化编辑步骤、JS 常用写法和检查命令见 [代码导读](代码导读.md)。

语言切换、单位三语名称配置与手动添加单位步骤见 [语言与单位扩展](语言与单位扩展.md)。主菜单会识别浏览器语言，未匹配时使用英文；根目录 reload_units.bat 用于扫描单位目录、校验素材并重建网页。

房主可在房间中选择地图和每位玩家的编组 COST 上限（默认3000），仅更换地图后所有玩家重新准备。玩家可自行选择队伍与空闲出生点，每人独立部署并操作自己的编组；同阵营共享回合，各自结束行动后交接。房间中房主金字、自己蓝字、其他玩家白字，聊天窗与操作区分别滚动。地图与多人规则见 [地图与多人房间配置](地图与多人房间配置.md)。

地图圆环按玩家视角显示：自己绿色、同队友军蓝色、敌军红色，均为俯视正圆。点击单位可查看所有者与队伍，非行动方也可查看。新增五台单位的原MOD接入、武器与数值说明见 [新增单位说明](新增单位说明.md)。

房主刷新或短暂断线时，在仍有其他真人在线的房间中保留10秒重连时间；主动离开立即移交，超时后按在线真人的加入顺序移交，跳过AI。换队或观战不改变房主身份。

房间玩家席位按“玩家ID／空位｜出生地｜准备状态”显示，观战名单每行三人。“加入队伍”由服务器选择该队当前空闲出生点，队伍满员或已经加入时有明确提示；也可点击空出生点直接选择。

房间和游戏共用聊天记录与发送频道选择。所有有权限查看的消息按顺序显示在同一个聊天面板中，以 `[全部]`、`[队伍1]`、`[队伍2]`、`[观战]` 前缀区分；切换发送频道不会隐藏其他频道消息。观战者的发送菜单只提供全部和观战，但聊天记录同时包含两队消息：

| 身份 | 全部频道 | 本队频道 | 另一队频道 | 观战频道 |
| --- | --- | --- | --- | --- |
| 队伍玩家 | 收发 | 收发 | 不可见 | 不可见 |
| 观战玩家 | 收发 | 只读队伍1 | 只读队伍2 | 收发 |

频道权限统一放在 `shared/chat-channels.js`；`shared/room-engine.js` 在实时发送、快照、重连和重复请求时校验权限。切换队伍或观战身份后，界面重新筛选可见历史；已经看过的消息无法撤回。每个房间最多保留最近100条消息。

房主通过 AI 行的设置按钮选择简单／中等／困难（75%／100%／125%性能）及50%～150%编组预算。AI独立阵营倾向已移除，改为遵守房间和所在队伍的禁用阵营、年代标签。最终编组可查看队友头像与总COST并修改自己的编组；先禁用标签不符或单机超限的单位，再从编组末尾向前禁用至总COST合规。超限显示OVER COST，禁用标签显示“不被允许的单位”，文字均位于黑色半透明遮罩上方；这些单位不会进入战场。详见 [遭遇战与阵营平衡](遭遇战与阵营平衡.md)。

聊天频道选择位于输入框左侧，消息格式为 `[队伍1]玩家ID:聊天内容`（全部／观战频道对应显示其频道名）。战斗演示由中央线分区，格斗单位接近对方区域完成攻击后返回，挥刀使用原MOD粉色／黄色序列帧，战斗Ring与地图Ring均为俯视正圆。


编组数量上限默认为12台，房主可在房间内设置3～12台；仅更换地图会取消准备，联机和离线房间使用相同规则。AI优先填满允许的单位槽位，在COST或阵营最低造价不足时减少台数，并随机选择合法武器套件。编组列表显示阵营、名称、图标、当前武器套件、COST和单位介绍；点击单位可查看详细属性并修改武器套件。导弹不再显示额外说明文。


房间默认编组COST为3000、单位COST上限500、每人最多6台（可设置3～12台）。进入房间前编组编辑器的两种COST上限均显示“无限”；保存本地编组不会按未加入的房间提前禁用单位。现有单位均带阵营与年代标签，如`EFSF,0079`或`ZEON,0079`，可按阵营和年代共同筛选。房间和队伍的禁用标签叠加，不修改本地已保存编组。队伍加入按钮位于对应队伍框右上角。房主可通过玩家行的“管理”调整到空出生点或观战席，开局后锁定其他玩家席位调整；可以踢出其他玩家并使其旧重连凭据失效。

新增`MS-06F2 扎古II F2后期型`，使用原MOD机体、独眼、武器挂点与攻击Step，18000耐久、5格移动，COST350～375，与吉姆同档。主武器套件为120mm机枪、380mm火箭筒、120mm对空机枪，固定携带铁拳与热能斧，不搭载光束武器。


每个AI的“编组数量比例”与“编组COST比例”分别设置，数量默认100%，可选50%、75%、100%、125%、150%、175%、200%。数量上限=房间单位数量上限×数量比例，向下取整，至少1台。例如房间上限12台时，50%为6台，200%为24台；真人玩家仍服从房间上限。AI仍受自己的COST预算、单机COST及房间/队伍禁用标签限制，优先填满可负担的合法槽位。三张预制地图的每个出生区均支持24台AI单位。


战斗左侧列表按所有者显示存活数/实际部署总数，只显示当前玩家所属队伍的单位，观战者显示双方；名称使用机体名称，HP下显示黄色EN条和行动状态。点击列表单位会选中并定位地图，保留较高缩放，默认全图视角下放大至175%。战斗中的房间席位页顶部按钮改为“返回战斗”，主菜单仍从战斗页进入。房间右侧可切换聊天/LOG，LOG与战斗场景共用当前房间的最新日志。房间和队伍的禁用阵营、禁用年代使用下拉菜单：选择标签可切换禁用，支持“不禁用”和“禁用全部”，关闭时显示已禁用标签。


战斗采用共同规划：本队玩家可同时操作自己的单位，选定攻击目标后显示计划箭头，并一直保留到本批演出开始；应战阶段向双方显示实线来袭攻击箭头；当前武器可反击的来袭者用黄色虚线箭头标记，可点击地图敌人、左侧全部来袭单位滚动列表或下拉框切换唯一反击目标，选中后机体转向该目标，黄色实线箭头标记选定的反击目标，确认后同步给所有玩家。暂不扣 EN 或造成伤害；可以取消计划后重新选择。本队所有参战玩家结束行动后，按目标机体合并来袭攻击，由该单位所有者统一选择反击、防御或回避；不同玩家同时处理各自的应战请求，同一玩家依次处理自己被攻击的单位，无需等待其他玩家；被集火时只需一次选择：反击先选武器，再从其射程内的来袭敌人中选择唯一目标；防御或回避统一应用于所有来袭攻击；所有选择完成后才统一按顺序结算并发布本批全部结果。选择期间不扣血、不扣 EN，反击次数与 EN 会预留，避免超额选择。结算完全部有效计划后进入整批演出阶段，所有等待名单中的人类玩家（含观战者）完成后才换队；胜利倒计时也从演出完成后开始。失去有效攻击方、目标或武器条件的计划自动跳过。相同格子仍由服务端判定占用，不能重叠移动。每个客户端直接在大地图同时播放本批所有交战（每场内先攻后反击），不弹出战斗窗口；地图坐标中的射击弹道、格斗接近与返回、推进回避、命中、电流与死亡爆炸沿用原素材。地图提供快速演出和跳过交战按钮，本机跳过仅确认本机完成，等待其他玩家完成后交接回合；应战时镜头平移到当前防守单位，不改变倍率；左侧显示进攻方信息，右侧显示防守方及应战手段，中间保留地图。进入交战播放时保持玩家当前的镜头位置和倍率，不自动平移或缩放。断线暂停、席位补位、重连、空出生点与 AI 使用同一套流程。

战斗演出的武器、命中和死亡等音效在现有音量上额外减半，倍率由 `assets/presentation.json` 的 `battleSfxVolume`（0.5）配置。

并行演出中的致命攻击会等待该单位此前已结算的交战和合法反击播放结束，避免单位爆炸隐藏后仍开火；无关交战仍并行。回避和近身移动的推进启动特效使用单位最终可见姿态，每个单位只画一次，避免多路来袭同时触发特效错位。

每台执行攻击或反击的单位独立抽取本地随机0～1秒起播延迟；反击在先攻结束后，使用反击单位自己的延迟。致命攻击仍遵守已有的先后依赖。暂停期间不推进延迟，恢复、快照同步不会重新抽取；随机演出不修改服务端判定或伤害。

房间中房主只显示“开始游戏”，无需准备；其余出战玩家全部准备且两队均有玩家或AI后，房主才能点击进入最终编组。全员准备、添加AI均不会自动开局。观战玩家不参与准备。

后台联机使用服务端WebSocket心跳及TCP保活，客户端每20秒发送轻量保活，不依赖画面刷新；服务端默认连续90秒无响应才判定失联。切回窗口或网页恢复运行时主动同步房间状态。真实断线仍显示重连弹窗。此连接处理修改需要更新并重启服务端。

部位破坏、地形命中修正及武器的新数值见 [部位破坏与地形规则](部位破坏与地形规则.md)。单位JSON中的零件强度、武器依赖部位和破坏系数来自原MOD；普通攻击、反击、AI与联机裁定共用同一检查，损坏状态重连后保留。

右上角“设置”可随时切换中/日/英文，调节总音量、音乐和音效。设置即时生效并在本浏览器保存，总音量与各通道音量相乘；100%使用当前原有混音音量。

# V98 至 V99 性能排查与持续优化

本轮按用户要求先发布既有功能为 V98，再持续排查 AI、渲染、演出与轮询。开始时间为东京时间 2026-11-08 02:36，至少两小时；发布收尾持续至约 05:30。V98 基准提交为 `7062e95b`，冻结 HTML 位于本机 build/performance-v98-baseline/client.html。

## 测量方法

- tools/performance-battlefield.cjs：固定混合单位或同一份真实战局，预热后测量90帧，包含总览、闲置、选中、切换选中、近景、连续缩放及缩放后状态；另记录首次绘制，可保存 CPU profile。
- tools/performance-live-battle.cjs：通过真实客户端启动离线 RoomEngine，可委托玩家AI；记录帧间隔、绘制、UI、AI、运输回收、长任务、资源和最慢战局。
- tools/performance-scene-soak.cjs：桌面与手机视口交替，反复同图重开或换图，混合单位、移动、缩放、暴雨、暴风雪、昼夜和阴影，检查资源释放和缓存上限，定期GC观察堆及DOM。

原始JSON和CPU采样保存在本机 build/performance-v98/，不纳入源码。390×844是桌面浏览器手机视口，不代表安卓硬件性能；CPU绘制耗时不等于GPU端到端FPS。长测存在并行压力，用于稳定性和热点发现；性能对照使用独立运行的相同场景。

## 实施的优化

### 规则查询与AI

- 可达范围、小队交集与绕障在一次查询内建立当前占格及预移动占格索引，避免每个候选格扫描全体单位。批量空投采用短期追加索引，每台落地后登记，保持落点顺序和随机调用。
- 视野计算在一次查询中复用传感器属性和占格；非全迷雾直接生成全图可视格。全迷雾输出采用稳定顺序，避免仅插入顺序变化触发重复更新，额外揭示格仍保留。
- 运输回收先排除不兼容母舰和容量不足，再计算敌军接触，全图回收搜索复用占格索引。
- 攻击探测先排除友军、死亡和射程外对象；同次UI刷新共享重复探测。
- 派生属性只在明确的只读查询、UI刷新或单次绘制内复用；不同上下文、虚拟演员、嵌套和异常均隔离，不跨命令或伤害结算缓存。
- AI连续运输查询按约8毫秒软预算分段让出事件循环，重新检查房间、战局与revision；人类操作或关闭房间使旧查询失效。保留行动节奏和服务端裁定。
- 增援、维修和库存预留按所有者及编组建立集合／计数；快照复用可见ID集合，隐藏事件只序列化一次；大厅摘要不变时不重复广播。
- 录像采集复用已深拷贝且只写一次的增量作为内部基线，公开回放仍独立重建。

### 客户端及表现生命周期

- 同次UI刷新只构建一次名字集合，无ID立即返回，减少面对方向查询和排序。
- 聊天历史不变时保留DOM；LOG只协调当前80行，保留重复文本和滚动位置，名字及语言变化仍更新。
- 重连倒计时仅在有效预留席位且页面可见时运行，移除永久全页250毫秒查询。
- 绘制使用ResizeObserver已知相机尺寸，避免缩放标签写入后立即强制布局。输入仍测量实际矩形；无ResizeObserver时保留实时回退。
- 静态外观队列只处理待更新项；受损MS可缓存，平台电流继续实时绘制。静态缓存条目由96改为256，但仍严格限制16M像素；阴影及瓦片各限8M像素。
- PNG加载后等待异步解码，代际检查覆盖解码回调；过期资源不能重入旧场景，菜单图标租约保留。
- 交战演出的未参战单位复用原对象，参战者仍应用独立演出状态。
- 新场景清理旧光照过渡，恒定光照直接返回端点，防止浮点噪声产生缓存变体。多零件合成阴影仍统一25%透明度。

## 轮询及生命周期复核

| 路径 | 当前行为及处理 |
|---|---|
| 战斗绘制 | 单一requestAnimationFrame入口；离开战斗取消，资源未就绪不绘制，隐藏标签页由浏览器节流 |
| AI调度 | 按房间及行动状态安排单次定时器；新查询分段让出，房间关闭或revision改变取消旧决策 |
| 房间重连文字 | 已去掉永久250毫秒全页扫描，仅有可见有效倒计时才启动 |
| 网络保活 | 保留20秒心跳及前台同步；与绘制独立，避免后台断线，未当作冗余轮询移除 |
| 大厅状态 | 仅连接选择页20秒更新，取消旧探测；已连接PING有独立清理 |
| 赛后／返回倒计时 | 仅对应弹窗期间250毫秒更新，重置时清理；不驱动战斗规则 |
| 图片、瓦片与天气 | 场景释放销毁派生画布并清理代际回调；菜单资源按租约保留，缓存逐项受预算限制 |

## 最终对照

同一300单位合成场景、90个稳定样本的CPU P95，单位毫秒。该对照关闭迷雾，使用晴天正午和默认关闭的单位阴影；阴影开启另由场景压力及透明度回归覆盖。切换选中包含UI、范围计算与绘制。

| 场景 | 1920×1080：V98 → V99 | 390×844：V98 → V99 |
|---|---:|---:|
| 总览 | 12.5 → 9.5 | 13.1 → 10.5 |
| 闲置 | 2.7 → 1.9 | 3.0 → 2.8 |
| 选中 | 4.1 → 2.6 | 4.4 → 3.3 |
| 切换选中 | 100.6 → 38.8 | 101.9 → 49.8 |
| 近景 | 2.7 → 2.0 | 2.4 → 1.7 |
| 连续缩放 | 8.8 → 6.0 | 11.2 → 8.5 |
| 缩放后 | 3.0 → 2.3 | 3.1 → 2.2 |

固定真实中期战局（204单位）：桌面切换选中P95为23.5→19.0毫秒、缩放10.5→8.0；手机视口分别30.9→26.3、12.7→9.9。首次绘制桌面62.8→51.2、手机视口59.0→41.5。手机视口总览11.1→11.4，未观察到改善，不将所有项目描述为提速。

全迷雾真实开局各约25秒：V98的20次超过50毫秒长任务降至V99的0次，最大帧间隔145.6→46.2毫秒，AI选择P95 7.6→1.8毫秒。实际推进128／142个revision，墙钟计时影响推进量，不是逐命令完全同序基准。

规则差分：360组路径、67种单位的13,344组目标探测、48组运输回收命令均与V98一致。路径总耗时510.6→283.6毫秒，回收336.0→141.7。204单位、300帧录像增量及重建内容一致，采集522.3→472.6毫秒。传感器比较覆盖三种迷雾、100／300／600单位的可见ID、雷达及可视格集合。规则查询加速不能直接换算整局FPS倍数。

## 长测及边界

前几轮真实战场运行约10、10、13分钟，推进至27、32、39回合；第三轮正常分出胜负。最终全迷雾委托对局13分03秒、第37回合正常结束，服务端258个单位对象、139台存活，无脚本错误。此轮同时运行阴影换图压力测试，绘制P95 9.9毫秒、堆采样约177MB，但仍出现最大约1.42秒帧间隔和976个长任务。

大规模后期交战峰值尚未完全消除，具体结算、首帧、资源和GC的比例仍需进一步隔离。本轮没有为强行分帧而暴露部分伤害结算，没有改动战力、奖励、库存及波次平衡。

换图长测包含同图重开和交替地图、桌面／手机视口、天气昼夜及合成阴影；严格检查缓存上限和释放后像素归零。25分钟内完成185次场景循环，无脚本错误，释放后派生画布像素归零，缓存均未超预算。DOM监听数量在1578至1651之间波动，无逐轮累积趋势；浏览器粗粒度堆采样从约123MB变为157MB，另用CDP精确堆采样复核，不能仅据粗粒度采样宣称没有内存增长。原始结果见本机 final-scene-soak.json。另以CDP精确统计运行5分钟、37次循环：GC后JS堆83.6→73.6→72.5→72.5 MiB，backing storage预热后约43.7 MiB，GC后DOM节点始终20,463、监听始终1,578；这一轮未见持续增长。

### 最后一轮独立后期采样

移除其他压力测试后，另运行12分钟全迷雾委托实战（启用CPU采样），推进至36回合、2,705个revision，服务端259个单位对象、141台存活，无脚本错误。绘制P95 8.1毫秒、UI刷新P95 2.2毫秒、AI选择P95 7.2毫秒、回收P95 0.1毫秒；帧间隔P95 15.1毫秒，但最大1,359毫秒，662次超过50毫秒长任务。原始结果为 final-isolated-long.json 和对应CPU profile。

调用栈确认仍有同步批量裁定片段约316毫秒、GC片段约168毫秒、录像采集片段约49毫秒。它们说明后续不能只继续调绘制缓存；但不能将它们单独认定为那次1.34秒峰值的全部原因。进一步拆分伤害裁定需要在私有战局副本上计算并原子提交，才能保持同批结果、服务端权威及revision一致性，本轮没有用暴露中间血量的方式冒险分帧。

复测命令示例（输出目录自动创建）：

```text
node tools/performance-battlefield.cjs --html public/client.html --sizes 300 --samples 90 --output build/perf/synthetic.json
node tools/performance-live-battle.cjs --fog full --delegate --stop-on-finish --duration 720000 --output build/perf/live.json
node tools/performance-scene-soak.cjs --shadows --duration 1500000 --output build/perf/scenes.json
```

### 最终Windows软件本体长测

最终提交构建的ProjectGreed.exe通过真实WebView2调试入口、隔离存档运行5分钟全迷雾AI对局，推进至20回合、1,311个revision，服务端160个单位对象，无脚本错误。帧间隔P95 8.1毫秒、最大408.1毫秒；绘制P95 5.9毫秒、最大103.3毫秒，159个长任务、最长394毫秒。原始记录为本机 final-native-live.json。此轮验证的是实际软件，并非浏览器仿真；场景规模和持续时间不同，不与12分钟样本直接比较。

最终Windows产品版本为0.99.0，源码标记f1b65e7c；该代码提交已推送main。本报告随后补充发布验证数据，未再更改游戏代码。软件本体复测使用隔离数据，测试房间与进程均已退出。

### 核对的历史失败

sensor-policy的2条原生传感器／旧浮点断言、ai-squads的1条无库存部署夹具、hangars的9条旧AP／容量／数值夹具、attack-aim-cell和auto-attack-draft共4条旧断言，已在V98复现，不计入通过数。

旧melee浏览器夹具在冻结V98上同样因undefined.at失败。Dom八弹道用例临时使用可写截图路径后，V98及V99均通过，没有为旧断言修改武器。

profile-storage一条诊断断言要求不导出外部键名，现行实现刻意导出键名及大小、不导出键值，V98同样失败；同组其余10条原生存储及回滚检查通过，本轮未改诊断格式。

并发AI测试补齐现行常规战库存；空投阻塞夹具改为注入批量放置查询，仍验证并发、公平、碰撞和落点。

发行清单校验：服务端81个文件、Windows 4,105个文件、安卓1个文件的SHA-256全部匹配。打包服务端在隔离端口验证HTTP首页V99及真实WebSocket创建房间／快照通过。文档链接及战斗规则生成一致性检查通过。

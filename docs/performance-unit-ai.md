# 单位管理与AI性能优化速报

日期：2026-11-03。基准为本轮修改前的V77（d744637f），同一台机器上的Node与Edge无头浏览器测试。以下是固定场景的本机CPU测量，不代表真实手机或公网联机的统一提升比例。

## 修改与测量

| 场景 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 单位库连续选择20台单位 | 1143.7 ms | 1.7 ms |
| 同次操作新增/移除列表行 | 2940 / 2940 | 0 / 0 |
| 32单位场景AI选点中位耗时 | 0.617 ms | 0.514 ms |
| 格纳库出击选点中位耗时 | 2.701 ms | 2.309 ms |
| 一次出击的战术评估次数（4个可加入小队的位置） | 5 | 1 |

- 单位库选择只更新选中状态和预算；无修改地关闭单位预览复用原列表。换装、经济或科技变化仍会刷新。头像延后解码、按需加载。
- 编组与战略部队列表一次建立载员索引，避免对每艘载具、每个格纳库重复扫描全列表；战略调动状态也按集合查找。
- 正常共享驾驶员存档跳过六份旧阵营驾驶员存档的读取和解析；旧存档需要时仍可迁移。
- AI每个候选位置只计算一次战术分数；夹击方向、友军分组、占点避让轮廓在本次搜索准备一次。缓存仅限本次搜索，不跨动作复用位置和兵力数据。
- 出击候选位置一次评分，直接复用结果选择同型号小队；战略兵力评估在一次决策内复用单元分值。
- 修复AI两台合流后因已移动而拒绝第三台空闲单位加入的问题。已有成员不会因此恢复行动。
- 清理普通攻击/反击路径中不再使用的AP求和，保留AP配置字段。

修改前后固定场景选出的普通行动和出击命令一致。现有集结、夹击、补给、运输、占点策略保留。

- 44项Node测试通过：AI战术、小队、路线与抱团、并发行动、预载员、嵌套运输、只读决策与出击重复计算检查。
- 6项浏览器测试通过：桌面/手机战略部队详情、96单位移动帧、单位库切换与关闭预览、换装刷新、旧驾驶员存档迁移、载员排列/换装自动保存/移除母舰。
- 96单位移动场景：每帧约5.9 ms（P95约13.4 ms），每帧0次小队全表扫描；未改动演出中的权威单位状态。此项为现状检查，没有声称相对基准的改善。
- 客户端构建通过，未构建服务端、开发者版、br或gz。
- 旧 `tests/formation-preloads.spec.cjs` 的8项用例仍点击已隐藏的 `#openFormation`，因而超时；没有算入通过数。当前导航的载员排列、装备持久化和移除母舰流程由本轮新回归覆盖。未运行166项历史失败的全量套件，也未进行实体安卓手机或公网压力测试。
